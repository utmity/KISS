対象はCtrl＋A〜Z長押しの代替実装です。文字キー単独の長押しは対象外です。

端末はUnihertz、Android 16。選択中IMEは`dev.utmity.titanime/.TitanImeService`でした。実行した統合テストはIMEへ入力を配送せず、KISSのpre-IME入口を直接呼び出します。したがって、この成功を日本語／英語IMEの動作確認済みとは扱いません。

## 端末統合テストの内容

- 通常文字・Shift入力を捕捉しない
- 未登録Ctrl入力を捕捉しない
- 登録済みCtrl短押しを消費し、入力しない
- Ctrl解放でキャンセルし、文字キーの残りイベントを消費する
- 別キーによるキャンセル
- キャンセルフラグ付きキー解放
- 仮想キーボードを対象外にする
- CtrlとShift／Alt／Meta／Fnの併用を対象外にする
- 無効設定時は捕捉しない
- タッチによるキャンセル
- Activityの停止によるキャンセル
- ウィンドウフォーカス喪失によるキャンセル
- 長押しで割り当てたAndroid設定アプリを起動し、待機中の余計な文字がない
- 26キーの設定項目と解除用の選択肢が存在する

## 検証中に修正した問題

1. 上流のDebug縮小設定では、テストランナーだけが使うKotlinランタイムが削除され、テスト開始前に落ちました。専用Debug版で縮小を無効にしました。Release設定は維持しています。
2. テストごとに連絡先設定を戻すと権限要求が保留され、後続テストのフォーカスを奪いました。テストクラス全体で連絡先プロバイダーを一時無効にし、最後に設定を戻すようにしました。連絡先権限は付与していません。
3. 起動先でキーを離すとKISSへ解放イベントが来ないため、次のショートカットを妨げないよう、フォーカスセッションをまたぐ新規押下で残留状態を解除しました。回帰テストを追加しています。

ビルド環境：Windows、Android SDK 36、Android Studio付属JDK 25.0.3、上流Gradle wrapper 9.8.2。デバッグ署名のAPKであり、配布ストア用のリリース署名ではありません。

実機の手動確認・導入・通常版への復帰は[T2E-keyboard-ja.md](T2E-keyboard-ja.md)を参照してください。
